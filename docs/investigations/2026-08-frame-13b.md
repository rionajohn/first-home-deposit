# Frame 13b: what the `[Visual aid]` placeholder actually specifies

Investigation only. No file outside this one was changed, and nothing was built.

- Screen: frame 13b, "Loan-to-Value - video and diagram". Figma node `103:293`.
- Route: `/learn/ltv/video`. Module: `src/screens/learn-ltv-video.js`.
- Copy: `src/content.js` under `'/learn/ltv/video'` (the placeholder is at line 626).
- Read on: 22 August 2026, against the working tree at `bcd0ded`.

---

## 1. The placeholder's specification, verbatim

Two keys, `src/content.js`:

```js
visualAidLabel: '[Visual aid]',
visualAidCaptionTemplate:
  'Diagram: the same {property} property at 95%, 90% and 85% Loan-to-Value, showing the deposit block growing and the loan block shrinking',
```

`{property}` is filled at render time in `learn-ltv-video.js`:

```js
fill(c.visualAidCaptionTemplate, { property: propertyValue !== null ? formatCurrency(propertyValue) : '' })
```

so a participant who set a £280,000 property target reads:

> Diagram: the same £280,000 property at 95%, 90% and 85% Loan-to-Value, showing the deposit block
> growing and the loan block shrinking

**How complete it is, measured against frame 18's.** Frame 18's brief named four items and their
order, which fixed everything except layout. This one is close to that but not equal to it. What it
fixes:

| Fixed by the brief | Left open |
|---|---|
| Three states, at 95%, 90% and 85% Loan-to-Value | Whether the three sit side by side or stack |
| One property value, held constant across all three | Orientation of the blocks (horizontal bars, vertical columns) |
| Two elements per state: a deposit block and a loan block | Whether each block is labelled, and with what |
| The direction of change across the three: deposit grows, loan shrinks | Whether the blocks carry amounts, percentages, both or neither |
| That it is blocks, i.e. proportional areas, not a line or a curve | Whether the participant's own deposit percentage is marked |

It also leaves open the thing frame 18's brief never had to answer, because frame 18's timeline was
identical for every participant: what the diagram does when the participant's own Loan-to-Value is
not one of the three drawn. See section 4.

**Does the surrounding copy already carry the explanation?** Item 8 is the whole conceptual
explanation, in one sentence, and it covers both halves of what the diagram is specified to show:
what Loan-to-Value is (the share that comes from a mortgage) and what changes as the deposit grows
(lower Loan-to-Value, better rates). Nothing on this sheet other than the placeholder itself
addresses the three-way comparison.

So on this screen the diagram would be a second rendering of item 8, not an addition to it. That is
a fair thing for a visual aid to be - it is what a visual aid usually is - but it is worth stating
plainly, because frame 18's timeline carried information (the four stages of buying a house, and
which one the participant was at) that no copy on frame 18 supplied.

## 3. How the screen is reached

From frame 13 (`/learn/ltv`) only. Its "Want more on this?" card holds two rows, and **both of them
open this same sheet**:

```js
['open-video', 'open-diagram'].forEach((action) => {
  container.querySelector(`[data-action="${action}"]`).addEventListener('click', () => {
    setState({ returnFrame: '/learn/ltv' });
    window.location.hash = '#/learn/ltv/video';

```
`src/screens/learn-ltv.js`

| Row | Label | Sub-label | Icon |
|---|---|---|---|
| 1 | "Watch: what Loan-to-Value means" | "1 min 20", plus " · Watched" once `ltvVideoSeen` is set | `playCircle` |
| 2 | "See it as a diagram" | "The same {property} home at 95%, 90% and 85%" | `chartBarCircle` |

Frame 13 itself is reached from the "What rates are like at this Loan-to-Value" row on frames 12, 15

**Yes, the media placeholder sits above the visual placeholder,** and this is the part worth
noticing. A participant who taps **"See it as a diagram"** - a row whose sub-label promises exactly
the three-way comparison the diagram would draw - lands on a sheet whose first element is a
non-working play control for a video they did not ask for, and has to read past it to reach a second
dashed box telling them the diagram is not drawn either. Two placeholders in a row, on a route
entered by asking for the second one.

Dismissing by any means (scrim tap, "Got it", or the drag gesture, which clicks the same dismiss
control per D18) sets `ltvVideoSeen = true` and returns to frame 13 - including when the participant
arrived by tapping the diagram row and never saw a video. Frame 13's video row then reads
"1 min 20 · Watched".

## 4. Figures on the screen, and whether a diagram would be participant-specific

**One figure reaches this screen: `property-value`.** It is the only state value
`learn-ltv-video.js` reads, and its only use is the `{property}` substitution in the placeholder
caption. Nothing else on the sheet is a number except the video duration, which is a literal.

There is no guard on the route, so `property-value` can be `null` (the caption then renders with an
empty gap: "the same  property at 95%..."). In practice 13b is only reachable through frame 13,
which does guard on `property-value` and `deposit-pct` and replaces itself with `/calculator/result`
if either is null.

**Would a diagram be participant-specific? Partly, and differently from frame 18's timeline.**

| Component of the diagram | Fixed or participant-specific |
|---|---|
| The three Loan-to-Value levels: 95%, 90%, 85% | **Fixed.** They are `CHART_DEPOSIT_PCTS = [0.05, 0.10, 0.15]` inverted, the same three the app plots everywhere (frame 12's chart, frame 13's table, frames 15/16's rate-band rows) |
| The relative size of the deposit and loan blocks at each level | **Fixed.** 5/95, 10/90, 15/85 are the same proportions for every participant |
| The property value the blocks are amounts of | **Participant-specific.** `property-value`, entered on frame 09 |
| Any cash amounts on the blocks | **Participant-specific**, derived from the above |

So the *shape* is identical for every participant and only the money differs - which is the opposite
way round from frame 18, where nothing at all varied.

**One case the brief does not cover.** The participant's own deposit percentage comes from
`DEPOSIT_PCT_OPTIONS`, and `learn-ltv.js`'s header records that two of its values (20% and 25%) fall
outside this fixed three-column set:

> frame 12b/09's chip row only ever offers `DEPOSIT_PCT_OPTIONS` values, three of which (5/10/15%)
> are exact matches and two (20/25%) fall outside this fixed 3-column table, in which case no column
> is highlighted.

A participant at 20% or 25% would be looking at a diagram of three Loan-to-Value levels, none of
which is theirs. Frame 13's table already has this property and handles it by highlighting no
column. The 13b brief says nothing about it either way.

## 6. Does anything already explain Loan-to-Value visually?

Yes, and most of it is on frame 13 - the screen this sheet opens from.

| Where | What it draws | Relation to the 13b brief |
|---|---|---|
| **Frame 13, `proportionRowsHTML`** | Two labelled bars with a percentage fill: "Your deposit" / "{pct} of the price", and "Mortgage" / "{pct} of the price - this is your Loan-to-Value" | **This is the deposit-block-and-loan-block idea, already drawn** - but at one Loan-to-Value only, the participant's own. It is the diagram's single frame, not its three-way comparison |
| **Frame 13, comparison table** | A 3-column table at 5/10/15% deposit with rows for Deposit, Loan-to-Value, Typical rate, Monthly, and Interest over the term | **This is the three-way comparison, already present** - numerically rather than visually, over exactly the 95/90/85% the brief names, for exactly the same property |
| Frames 15/16, rates card | `rangeFigureHTML` (a rate range with a position marker) plus three `rateBandRowHTML` rows at three deposit amounts | Adjacent - it plots rate against deposit, not the price split |
| Frame 12 | "Why a bigger deposit helps": three text rows, and a link "What is Loan-to-Value?" | Textual only, no visual |

**So the specific answer to the question asked:** frame 13's `proportionRowsHTML` already does half
the job the 13b diagram specifies. It renders the price as a deposit block and a loan block, labelled
and captioned with their percentages, at the participant's own figures. What it does not do is show
three of them at once, which is the whole point of the 13b brief ("the same property at 95%, 90% and
85%... the deposit block growing and the loan block shrinking"). The growing-and-shrinking is only
legible across a set; one pair cannot show it.

The three-way comparison is not missing from the app either - it is frame 13's table, one screen
back, in numbers. A 13b diagram would therefore be a visual restatement of frame 13's table using
frame 13's own proportion-bar vocabulary, rather than information the app does not currently carry.

### Two things anyone building here would hit

Recorded because they are facts about the current code, not suggestions.

- **`proportionRowsHTML` is a track with a percentage-width fill** (`components.css`
  `.proportion-row__track` / `.proportion-row__fill`, 6px tall). `DESIGN.md` excludes segmented bars
  for proportions; these are one bar per part rather than one bar divided into parts, which is
  presumably why they stand. Anything that puts three such pairs side by side would want the same
  question answered explicitly, as D36 had to answer it for frame 18's timeline.
- **This sheet is already tight for space.** `GAPS.md` records 13b overflowing its viewport by 61px,
  and separately records its flag row being squeezed at the large text size (the overlap test "fails
  on exactly these three cases (32 default, 32 large, 13b large)" before the fix). A diagram added
  between items 10 and 11 lands in a sheet that already scrolls.

## Verdict

**It is a specified-but-undrawn visual, not a vague note** - the same category as frame 18's, though
not quite as complete.

It reads as a brief because it fixes what to draw and how many: three states at named Loan-to-Value
levels, one property value held constant, two named blocks per state, and the behaviour that makes
the point ("the deposit block growing and the loan block shrinking"). That is enough to build from
without inventing content, which is the test frame 18's brief passed.

Three things separate it from frame 18's, and they are the ones to weigh:

1. **It is participant-specific in a way frame 18's was not.** The shape is fixed for everyone; the
   amounts are not, and the brief does not say whether amounts appear at all.
2. **Its content is already on the screen it opens from,** as a table with the same three columns
   over the same property. Frame 18's timeline had no counterpart anywhere in the app.
3. **Its vocabulary already exists too** - frame 13's deposit-and-mortgage proportion bars are the
   single-level version of the same drawing.

It is also worth separating the placeholder from the route into it. The strongest finding here is not
about the diagram: it is that "See it as a diagram" on frame 13 is a live control, contrary to what
D8 and G17a both record, and that it lands the participant on a non-working video placeholder before
they reach the missing diagram they asked for.
